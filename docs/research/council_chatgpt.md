# ChatGPT, раунд 1 (Thinking, ~3,5 мин, ~4450 слов, файл ТЗ.md) — ключевое
Имя: Landscape Renderer (landscape-renderer). MIT.
Принципы: CAD — источник геометрии, не второй CAD; детерминизм (seed, версии пакетов); локально; сначала графическая дисциплина, потом эффекты; пакеты декларативные без исполняемого кода.
Стек MVP: Python 3.12 + PySide6/Qt Widgets (LGPL-модули), CPU-рендер NumPy/OpenCV/Pillow, shapely; интерфейс RendererBackend для будущего GPU/другого UI. Веб (FastAPI+React) — не для MVP: Node-сборка + Python-процесс, безопасность локального HTTP, сложная упаковка. Плагин CAD — адаптер в v2.
Требования с ID и приоритетами P0/P1/P2: IMP-001..008, MAP-001..006, REN-001..009, EXP-001..009.
- явный выбор layout+viewport, единицы — не угадывать, предупреждать; видимость/заморозка слоёв во viewport; SHA-256 источника, «источник изменился».
- маппинг: пользователь → профиль → автоподбор; 3 состояния: подтверждено/предложено/не сопоставлено; словарь синонимов RU/EN; «ГОСТ-слоёв» как единого стандарта нет — настраиваемый профиль + импорт CSV/JSON.
- рендер: scene graph в мм листа; слои: бумага, покрытия, посадочные пятна, растения, контуры, собственные тени, падающие тени, фактура, аннотации; линии в мм бумаги; единый свет; seed; превью 1/2–1/4.
- экспорт: PNG/PDF с физ. размером и DPI; режимы «только viewport» / «весь лист»; отчёт о несопоставленных; исходник НЕ перезаписывать.
- В DWG: AutoLISP-скрипт (v1) вставляет PNG в paper space, слой LANDSCAPE_RENDER, стабильный ID через XData, повторный запуск обновляет, а не дублирует; PNG = внешняя ссылка → ETRANSMIT. ezdxf DWG не пишет. Плагины CAD — v2.
DWG: ODA File Converter, установленный пользователем, не перераспространять до юр. проверки; LibreDWG (GPLv3) не в MIT-стек.
Пакет .lspack (ZIP): manifest.json (schema_version, id reverse-DNS, version, app_compatibility, authors, license, license_file, contents, files с sha256), LICENSES.md, README, preview.png, plants/<id>/plant.json + SVG варианты, brushes/, styles/, rules/. SVG санитизировать.
plant.json: id, common_name{ru,en}, scientific_name, tags, nominal_crown_diameter_m, variants[{id,file,weight}], anchor, default_height_m, shadow{...}.
Правила YAML/JSON: match{entity_type, layer_any glob, block_any, attribute_exists}, assign{semantic_class, style, plant_id_from_attribute, crown_diameter_from_attribute, diameter_unit}; priority, затем специфичность; равенство = ошибка конфигурации; regex опционально с защитой.
Проект .lscapeproj: source{path, sha256, format}, target{layout, viewport_handle, mode}, mapping_profile{id,version}, packs[{id,version,sha256}], style, render{dpi,paper,seed,light_azimuth_deg}, output.
Графика: линии 0,10–0,13 / 0,18 / 0,25 / ≤0,35 мм; бумага видна; вариативность без шума; штрих в единицах бумаги; не добавлять деталей, которых нет в проекте; тень не перекрывает подписи; Beer-Lambert ≠ сам по себе акварель; K-M — исследование v2; libmypaint не обязательна; Rough.js не нужен («шероховатость усиливает мультяшность»).
Производительность: A1 300 dpi ≈ 9933×7016 = 69,7 Мпикс; тайлы 1024 с halo; превью ≤2 с из кэша/≤5 с первично; A3 8–15 с; A1 ≤60/120 с; ≤4 ГБ.
Тесты: синтетические DXF (simple_site, multiple_layouts, units_mm_m, viewport_frozen_layers, block_attributes кириллица, a1_stress, битые атрибуты); unit на viewport/единицы/толщины; golden images с seed; SSIM; PNG/PDF размеры; кириллица в путях; CI Windows. Художественная приёмка: ≥3 практикующих архитектора, 5–10 листов, ≥4/5 по каждому критерию.
Репо: README, LICENSE, CONTRIBUTING, CODE_OF_CONDUCT, SECURITY, pyproject, uv.lock, docs/{ARCHITECTURE, FORMAT_SPEC, GRAPHIC_STYLE_GUIDE, BENCHMARKS, decisions/}, src/landscape_renderer/{cad,mapping,scene,render,packs,project,export,ui}, packs/{starter-plants,starter-styles,profiles}, tests/{fixtures/dxf,golden,unit,integration}, .github/workflows.
Roadmap: MVP (DXF, layout/viewport, правила+отчёт, CPU-рендер, PySide6, PNG/PDF, проект, golden) → v1 (менеджер пакетов, пресеты масштаба, профили CAD, AutoLISP-вставка, инкрементальный рендер, гайды) → v2 (GPU, плагины CAD, clip/xref, K-M, пастель, редактор символов, AI-вариации).
Риски с мерами (DWG, ODA, viewport, мультяшность, A1 память, дрейф пакетов, лицензии ассетов, scope creep, потеря PNG при передаче DWG).
Сообщество: код MIT, ассеты CC0/CC BY 4.0 отдельно; PR без ясного происхождения ассетов не принимать; GIF «один участок в трёх стилях».
Итог: «не начинать с универсальной цифровой акварели» — геометрия/масштаб, иерархия линий, убедительные растения.

# ChatGPT, раунд 2 — ответ на позиции Gemini
1) Стек: условно принял Tauri+React+PixiJS+Python sidecar «если команда готова поддерживать два стека и есть фронтенд-компетенции»; PySide6 — «если приоритет быстрее довести Python-прототип до надёжного продукта». Тезис «фронтендеров на порядок больше» без статистики не доказан.
   (Gemini в это же время принял PySide6 → консенсус по условию: один разработчик + ИИ ⇒ PySide6.)
2) DWG: нужны ОБА пути: AutoLISP/CAD-адаптер для AutoCAD (XData-ID, обновление без дублей) + самостоятельный экспорт DXF-копии с IMAGE для BricsCAD/nanoCAD/ZWCAD. IMAGE ссылается на внешний PNG → отдавать комплект (dxf + png, относительные пути). ODA — конвертер форматов, не API для безопасного редактирования DWG. Оригинал не перезаписывать. Совместимость IMAGE проверять тестами в каждой CAD.
3) Метрики по маскам/классам, а не глобально: чистота бумаги на маске фона ≥85% пикселей L*≥94, C*ab≤4; доля белого 30–60% — ориентир, не критерий; насыщенность окрашенных: медиана S≤0,40, P90 S≤0,70 (по классам: цветок ≠ газон); толщины на отдельной маске линий: основные 0,25–0,35, вторичные 0,15–0,22, детали 0,10–0,13 мм; отношение главных/тонких ≥1,8; ≥3 тональных уровня у контрольных крон. Калибровать на 10–20 одобренных листах.
4) Glob по умолчанию, regex — расширенный режим; профили сопоставления (как чертёж → семантика) отдельно от стилей (как семантика → рисунок); стиль может нести примеры профилей.
5) Добавить: (1) ручная правка объекта (вариант, поворот, масштаб, стиль, видимость, назначение) — MVP/P1, переживает пересборку, устойчивые ссылки на сущности; (2) дифференциальное обновление (добавлено/изменено/удалено) ОТДЕЛЬНО от проектных статусов сохраняемое/удаляемое/новое; (3) легенда/экспликация из тех же семантических объектов; (4) сезонные палитры — структура данных в MVP, рендер в v2; (5) печать/лист: преобразования модель↔viewport↔лист, тонкие линии на 300 dpi, PDF A1/A3; (6) контракты расширений и происхождение ресурсов.
