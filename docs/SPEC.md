# Техническое задание
## Открытый редактор ручной подачи планов ландшафтного дизайна

**Рабочее название:** Landscape Renderer (`landscape-renderer`)
**Лицензия кода:** MIT. Ассеты (символы растений, кисти, бумага) — CC0 / CC BY 4.0 с атрибуцией по файлу.
**Статус:** ТЗ на MVP и дорожная карта. Числовые пороги — стартовые значения, калибруются на эталонных листах.

> ТЗ сведено из совещания трёх моделей: Claude (Anthropic) — автор прототипа и брифа, ChatGPT (OpenAI) и Gemini (Google) — независимые ТЗ и два раунда перекрёстной критики. Протокол разногласий и принятых решений — в разделе 15.

## 1. Назначение

Программа превращает рабочий чертёж ландшафтного проекта (DXF/DWG) в подачу «от руки» — перо, карандаш, маркер, акварель, пастель и их сочетания — без ручной перерисовки. Пользователь выбирает лист и видовой экран; программа по правилам «слой / блок / атрибут → элемент подачи» строит иллюстрацию в масштабе листа. После правки чертежа подача пересобирается тем же нажатием.

Это духовный наследник Autodesk Impression (развитие прекращено около 2009 года; открытого аналога нет).

**Масштабы:** 1:50 – 1:500. **Объекты:** частные сады, участки, скверы, дворы.

### 1.1. Принципы

1. **CAD — источник правды.** Программа не редактирует геометрию и никогда не перезаписывает исходный файл.
2. **Детерминизм.** Одинаковые входные данные, версии пакетов, настройки и `seed` дают одинаковый результат.
3. **Только локально.** Чертежи заказчиков никуда не отправляются; сеть для работы не нужна.
4. **Сначала графическая дисциплина, потом эффекты.** Масштаб, иерархия линий, сдержанный тон и белая бумага важнее имитации краски. Главный найденный на прототипе риск — «мультяшность»: одинаковый толстый контур и сочные заливки.
5. **Открытые декларативные данные.** Растения, стили, кисти, профили — пакеты без исполняемого кода.

### 1.2. Не входит в объём

- Редактор CAD, черчение, правка геометрии DWG/DXF.
- 3D, перспективы, фотореализм.
- Нейросеть в рендере листа (допускается только как офлайн-инструмент подготовки ассетов, v2).
- Облако, аккаунты, синхронизация.
- Обещание совместимости «с любым стандартом слоёв» без профиля и настройки.

## 2. Пользователи и сценарии

| Роль | Задача |
|---|---|
| Ландшафтный архитектор / дизайнер | Быстро получить презентационный лист из рабочего DWG и обновлять его при правках проекта |
| CAD-специалист бюро | Настроить профиль сопоставления под стандарт слоёв бюро один раз |
| Художник / контрибьютор | Делать и публиковать пакеты растений, стилей, кистей без программирования |
| Разработчик | Улучшать ядро, NPR-алгоритмы, адаптеры CAD |

**Основной сценарий**
1. Открыть DXF (или DWG — через установленный ODA File Converter).
2. Выбрать лист (layout) и видовой экран; программа показывает масштаб, габариты, предупреждения по единицам.
3. Выбрать профиль сопоставления; проверить предложенные соответствия, исправить сомнительные. Увидеть список несопоставленных объектов.
4. Выбрать стиль; на превью поправить тон, толщины, свет, тени, бумагу; при необходимости точечно переопределить отдельные объекты.
5. Экспортировать PNG/PDF и/или комплект «DXF-копия + PNG» для вставки в лист.
6. Изменить чертёж в CAD → «Обновить» → увидеть список изменений источника → пересобрать.

## 3. Функциональные требования

Приоритеты: **P0** — MVP, **P1** — v1, **P2** — v2+.

### 3.1. Импорт (IMP)

| ID | Пр. | Требование |
|---|---|---|
| IMP-01 | P0 | Читать DXF (ezdxf): layouts, VIEWPORT, слои (цвет, тип, толщина, видимость), LWPOLYLINE/POLYLINE, LINE, ARC/CIRCLE, HATCH (границы), INSERT + ATTRIB, TEXT/MTEXT, DIMENSION (как аннотации) |
| IMP-02 | P0 | Явный выбор layout и viewport. Масштаб 1:N из `view_height` и высоты экрана; показать N, окно модели, размер на листе |
| IMP-03 | P0 | Единицы: читать `$INSUNITS`; при отсутствии — спросить; никогда не угадывать молча |
| IMP-04 | P0 | Блоки растений: имя блока + атрибуты (напр. `ВИД`, `D`); учитывать вставку, поворот, масштаб; единицы `D` — из профиля |
| IMP-05 | P0 | Видимость: выключенные/замороженные слои, заморозка во viewport; неподдержанное — в отчёт |
| IMP-06 | P0 | DWG → DXF **средствами CAD пользователя**: «Сохранить как DXF», либо автоматически через его AutoCAD (`accoreconsole` + скрипт `DXFOUT`) / BricsCAD. Опционально — ODA File Converter, установленный пользователем, **только если его лицензия это допускает**: без членства в ODA конвертер разрешён лишь для некоммерческого использования. Конвертация во временную папку, код возврата и лог в отчёт; конвертер в инсталлятор не входит |
| IMP-07 | P0 | SHA-256 источника; при изменении — «источник изменился», без автоперезаписи |
| IMP-08 | P1 | Повёрнутые и подрезанные (clip) видовые экраны, внешние ссылки (XREF), динамические блоки |

### 3.2. Сопоставление (MAP)

| ID | Пр. | Требование |
|---|---|---|
| MAP-01 | P0 | Правила по: типу сущности, имени слоя, имени блока, наличию/значению атрибута и их комбинации |
| MAP-02 | P0 | Порядок разрешения: ручное назначение → профиль (priority, затем специфичность) → подсказка автоподбора. Равные priority и специфичность = ошибка конфигурации |
| MAP-03 | P0 | Маски glob по умолчанию; regex — расширенный режим с защитой от катастрофического backtracking |
| MAP-04 | P0 | Три состояния объекта: **подтверждено / предложено / не сопоставлено**. Автоподбор никогда не назначает класс молча |
| MAP-05 | P0 | Автоподбор по нормализованным именам и словарю синонимов RU/EN (газон/lawn, гравий/gravel, водоём/water/pond, настил/deck, дерево/tree, кустарник/shrub, цветник/bed …) |
| MAP-06 | P0 | Импорт/экспорт таблицы сопоставлений CSV/JSON; сохранение своего профиля |
| MAP-07 | P1 | Стартовые профили: Land F/X, Vectorworks Landmark, русскоязычный пример. «ГОСТ-слоёв» как единого стандарта нет — это настраиваемый пример, а не правило |
| MAP-08 | P0 | Профили сопоставления хранятся **отдельно** от стилей: профиль отвечает «что это», стиль — «как рисовать» |

### 3.3. Сцена и рендер (REN)

| ID | Пр. | Требование |
|---|---|---|
| REN-01 | P0 | Единый граф сцены в **миллиметрах листа**; у каждого объекта — происхождение (handle, слой, блок, атрибуты), семантический класс, высота, seed |
| REN-02 | P0 | Слои рендера (снизу вверх): бумага → покрытия (газон, мощение, гравий, вода, настил) → посадочные пятна → падающие тени → растения (тон, собственная тень) → линии → аннотации CAD → фактура бумаги |
| REN-03 | P0 | Стили: перо, маркер, акварель, карандаш, перо + акварель, перо + маркер. Пастель — P1 |
| REN-04 | P0 | Все толщины и размеры штриха/зерна — в мм бумаги; DPI участвует только в растеризации |
| REN-05 | P0 | Один азимут и высота света на лист. Собственная тень (от света, символ можно вращать) и падающая тень (по высоте объекта) — разные слои; тень не перекрывает надписи и размеры |
| REN-06 | P0 | Растения: силуэт по диаметру `D`, листовые кластеры, ≥3 тональных уровня, просветы бумаги, вариации по seed; деревья, хвойные, кустарники, живая изгородь, посадочные пятна (миксбордер) |
| REN-07 | P0 | Превью в 1/2–1/4 разрешения в фоновом потоке; инкрементальный пересчёт затронутых слоёв |
| REN-08 | P0 | Аннотации CAD (TEXT/MTEXT, размеры, экспликация) выводятся поверх подачи векторно, с корректной подстановкой шрифтов SHX/TTF (таблица замен, шрифты фиксируются для golden-тестов) и остаются читаемыми |
| REN-09 | P1 | Пресеты масштаба 1:50 / 1:100 / 1:200 / 1:500 (плотность штриха, размер кластеров, зерно) |
| REN-10 | P2 | Сезонные палитры (весна/лето/осень/зима) — структура данных закладывается в P0 |

### 3.4. Работа с объектами (OBJ)

| ID | Пр. | Требование |
|---|---|---|
| OBJ-01 | P0/P1 | Ручное переопределение отдельного объекта по клику: вариант символа, поворот, масштаб, стиль, видимость, тень, назначение класса. **Переживает пересборку.** Ключ объекта — не только handle (он может измениться при конвертации DWG→DXF или пересохранении в другом CAD), а составной отпечаток: handle + тип + слой + имя блока + атрибуты + геометрический отпечаток (центр, габарит). При однозначном совпадении переопределение переносится, при неоднозначном — пользователь подтверждает перепривязку; молча не переносить |
| OBJ-02 | P1 | Проектные статусы **существующее / удаляемое / новое** (из слоя или атрибута) с отдельной графикой (например, удаляемое — перечёркнутая крона). Не путать с diff изменений DWG |
| OBJ-03 | P1 | Автоэкспликация растений: вид, обозначение, количество, D — из тех же семантических объектов, что и рендер |
| OBJ-04 | P0 | Отчёт об изменениях источника: добавлено / изменено / удалено с прошлой сборки |

### 3.5. Экспорт и возврат в CAD (EXP)

| ID | Пр. | Требование |
|---|---|---|
| EXP-01 | P0 | PNG с физическим размером и DPI (150/300); PDF с точным форматом листа |
| EXP-02 | P0 | Режимы: «только видовой экран» и «весь лист» (с рамкой и штампом из paper space) |
| EXP-03 | P0 | **DXF-копия с IMAGE** в paper space на границах viewport, слой `LANDSCAPE_RENDER`. Отдаётся **комплектом**: `*.dxf` + `*.png` с относительными путями — IMAGE в DXF ссылается на внешний файл. Совместимость подтверждается матрицей испытаний (AutoCAD, BricsCAD, nanoCAD, ZWCAD); до испытаний универсальная совместимость не обещается |
| EXP-04 | P1 | AutoLISP-скрипт для AutoCAD: вставка/обновление PNG в нужном листе, стабильный ID через XData, повторный запуск обновляет, а не дублирует. Предупреждение о передаче PNG вместе с DWG (ETRANSMIT) |
| EXP-05 | P0 | Исходный DWG/DXF никогда не изменяется |
| EXP-06 | P0 | Отчёт: сопоставлено / пропущено / предупреждения (единицы, видимость, неподдержанные сущности) |
| EXP-07 | P2 | Нативные плагины AutoCAD/BricsCAD с кнопкой «Обновить подачу» |

### 3.6. Пакеты (PKG)

| ID | Пр. | Требование |
|---|---|---|
| PKG-01 | P0 | Установка/подключение пакетов `.lspack`; проверка схемы, версии, лицензии, sha256 (хешируются все файлы, кроме самого `manifest.json`); безопасная распаковка ZIP (запрет `..`, абсолютных путей, ссылок, лимиты размера) |
| PKG-02 | P0 | Никакого исполняемого кода в пакетах; SVG санитизируется (без внешних ссылок и скриптов) |
| PKG-03 | P1 | Менеджер пакетов в UI; руководство автора пакета |

## 4. Архитектура

### 4.1. Решение по стеку

**MVP: Python 3.12 + PySide6 (Qt Widgets, только LGPL-модули).**

- Ядро — отдельная **headless-библиотека и CLI** (`landscape-renderer render project.lscapeproj`): рендер без UI, для CI, пакетной обработки и будущих фронтендов.
- UI — тонкий слой над ядром.
- Интерфейс `RendererBackend` — чтобы позже добавить GPU-рендер или веб-UI (Tauri + React + PixiJS) поверх того же ядра без переписывания модели.

Обоснование: прототип рендера уже на Python; на старте команда — один разработчик и ИИ-ассистенты; один процесс без IPC, sidecar и локального HTTP API; один инсталлятор (PyInstaller/Nuitka). Плагины CAD — адаптеры в v2.

### 4.2. Конвейер

```
DXF  (DWG → ODA → DXF)
  → cad/      адаптер ezdxf → независимые от ezdxf сущности с происхождением
  → cad/      viewport transform: модель → мм листа, единицы
  → mapping/  профиль + ручные назначения → семантические объекты (+ статус сопоставления)
  → scene/    граф сцены: геометрия, класс, высота, переопределения, seed
  → render/   слои → композиция (тайлы) → PNG/PDF
  → export/   DXF-копия с IMAGE, AutoLISP, отчёт
```

### 4.3. Модули

| Модуль | Ответственность |
|---|---|
| `cad` | Чтение DXF, ODA-обёртка, единицы, viewport transform, аннотации |
| `mapping` | Профили, glob/regex-матчер, синонимы, автоподбор, отчёт |
| `scene` | Граф сцены, переопределения, статусы, diff источника |
| `render` | Бумага, заливки, растения, тени, линии, композитор, тайлы, кэш |
| `packs` | Схемы, валидация, безопасная загрузка ассетов |
| `project` | Формат проекта, хеши, версии |
| `export` | PNG/PDF, DXF+IMAGE, AutoLISP, экспликация |
| `ui` | PySide6: окно, превью, правила, стили, переопределения |

### 4.4. Рендер и производительность

- CPU (NumPy / OpenCV / Pillow; Numba по профилировке) — эталон корректности.
- Экспорт тайлами 1024×1024 с перекрытием (halo) под размытия и краевые эффекты.
- Маски в `uint8/uint16`, `float32` — только где измеримо нужно; итог sRGB.
- GPU — только после профилирования (v2), без привязки к CUDA/конкретной карте.

| Метрика | Цель (опорная машина фиксируется в `BENCHMARKS.md`) |
|---|---|
| Превью типового участка | ≤ 5 с первично, ≤ 2 с из кэша |
| A3, 300 dpi | 8–15 с |
| A1, 300 dpi (≈ 9933×7016 px) | ≤ 60 с типовой, ≤ 120 с сложный |
| Пиковая память A1 | ≤ 4 ГБ, иначе понятная ошибка, а не падение |

## 6. Графика: «архитектурно, не мультяшно»

1. **Иерархия линий** (мм на печати): детали 0,10–0,13; вторичные 0,15–0,22; основные 0,25–0,35; акцент (здания) до 0,5. Отношение основных к тонким ≥ 1,8. Одинаковый жирный контур вокруг каждого объекта — запрещён как стиль по умолчанию.
2. **Архитектура — под линейку**, «от руки» — только озеленение и мягкие покрытия; дрожание тонкое и оправданное.
3. **Тон**: прозрачные сдержанные заливки, бумага видна; ≥ 3 оттенка на цвет; часть крон плоская, часть объёмная.
4. **Порядок как в ручной подаче** (методика кафедр): контур → светлый тон → собственная тень → падающая тень → детали.
5. **Масштаб штриха** соразмерен печати (принцип UC Davis hybrid rendering): при 1:50 → 1:500 штрих не раздувается и не исчезает.
6. **Свет один на лист**; тени — отдельные слои, легче основной геометрии, не перекрывают подписи.
7. **Не добавлять несуществующих деталей**, которые можно принять за проектные элементы.
8. **Акварель**: полупрозрачные лессировки, неоднородность пигмента, зерно, краевое затемнение (Beer–Lambert как приближение). Kubelka–Munk — исследовательский модуль v2.
9. **Не нужны в ядре**: Rough.js (шероховатость усиливает мультяшность), libmypaint (полезна только для свободного рисования, v2).

## 7. Тестирование и приёмка

### 7.1. Эталонные данные (синтетические, без чертежей заказчиков)
`simple_site.dxf`, `multiple_layouts.dxf`, `units_mm_m.dxf`, `viewport_frozen_layers.dxf`, `block_attributes_cyrillic.dxf`, `statuses.dxf`, `a1_stress.dxf`, файлы с битыми атрибутами.

### 7.2. Автотесты
- Unit: viewport transform, единицы, толщины в мм → px, порядок правил, glob/regex, переопределения.
- Интеграция: чтение DXF, отчёт сопоставления, сохранение/загрузка проекта, кириллица и пробелы в путях, битые пакеты, несовместимые схемы.
- Golden-изображения малых сцен с фиксированным seed + SSIM (стартовый порог 0,88, калибруется).
- Экспорт: пиксельный размер, физический формат PDF, метаданные DPI, положение без сдвига.
- **Метрики качества по маскам классов** (стартовые, калибруются на 10–20 одобренных листах):

| Метрика | Порог |
|---|---|
| Чистота бумаги на маске фона | ≥ 85 % пикселей L\* ≥ 94, C\*ab ≤ 4 |
| Доля белого на листе | 25–60 % — ориентир, не критерий |
| Насыщенность окрашенных пикселей (по классам) | медиана S ≤ 0,40, P90 ≤ 0,70 |
| Толщины на отдельной маске линий | основные 0,25–0,35; вторичные 0,15–0,22; детали 0,10–0,13 мм |
| Иерархия пера | отношение медиан основные/тонкие ≥ 1,8 |
| Вариативность крон | ≥ 3 тональных уровня у контрольных крон |

- CI: Windows первым, затем Linux; проверка лицензий/SBOM; сканирование SVG и путей в архивах.

### 7.3. Художественная приёмка
≥ 3 практикующих ландшафтных архитектора оценивают 5–10 эталонных листов по 1–5: иерархия линий, читаемость проектной информации, убедительность растений, различимость покрытий, естественность техники, отсутствие «мультяшности», качество печати. Выход MVP — ≥ 4/5 по каждому критерию без критических дефектов читаемости.

## 9. Дорожная карта

**MVP** — доказать ценность и графический язык
- DXF, выбор layout/viewport, единицы; DWG — через CAD пользователя (`accoreconsole`) или ODA с учётом лицензии.
- Профиль правил, редактор сопоставлений, отчёт о несопоставленных.
- CPU-рендер: покрытия, деревья/хвойные/кусты/изгородь по блокам и атрибутам, посадочные пятна, иерархия линий, единый свет, тени, бумага.
- Стили: перо, маркер, акварель, перо + акварель, перо + маркер.
- PySide6: открыть / обновить, превью, слои, стиль, seed, переопределения объектов, экспорт.
- PNG/PDF A3/A1, DXF-копия с IMAGE (комплект), проект `.lscapeproj`, CLI.
- Эталонные DXF, golden-тесты, стартовые пакеты растений и стиля под CC0/CC BY.

*Готовность MVP:* архитектор на эталонном DXF сам сопоставляет слои и блоки, получает читаемую подачу, повторяет её после правки чертежа и экспортирует печатный PNG/PDF без потери масштаба.

**v1** — для регулярной работы
- Менеджер и валидатор пакетов; руководство автора пакета.
- Профили Land F/X, Vectorworks, русский пример; импорт CSV.
- Проектные статусы, автоэкспликация, пресеты масштаба, карандаш и пастель.
- AutoLISP-вставка/обновление в AutoCAD; инкрементальный рендер; diff источника.

**v2** — по доказанной потребности
- GPU/WebGPU-бэкенд после профилирования; веб-UI поверх ядра.
- Плагины AutoCAD/BricsCAD; clip-viewport, XREF.
- Сезонный рендер; Kubelka–Munk; libmypaint и ручное подрисовывание.
- Офлайн-генерация вариаций символов нейросетью с ручной проверкой и лицензией.

## 10. Риски

| Риск | Мера |
|---|---|
| Разнообразие DWG/DXF, прокси-объекты | DXF как контракт; список поддерживаемых сущностей; эталонные файлы; честный отчёт |
| Лицензия конвертера DWG | ODA File Converter без членства — только некоммерческое использование. Основной путь для бюро — DXF из собственного CAD (вручную или через `accoreconsole`); ODA — опция с предупреждением о лицензии |
| Неверный масштаб/положение | Отдельный модуль transform; тесты единиц и физических размеров; предупреждения |
| «Мультяшность» | Графический регламент (раздел 6), метрики по маскам, приёмка архитекторами |
| Память и время на A1/A0 | Тайлы, кэш, уменьшенное превью, бенчмарки |
| Визуальный дрейф при обновлении пакетов | Версии + sha256 в проекте, фиксированный seed, закреплённые версии зависимостей и шрифтов |
| Потеря ручных правок после изменения DWG | Составной ключ объекта (OBJ-01), подтверждение перепривязки, отчёт |
| Лицензии ассетов и зависимостей | Реестр лицензий, SBOM; без GPL-компонентов в ядре; PR без ясного происхождения ассетов не принимаются |
| Расползание объёма | Один сквозной сценарий DXF → правила → подача → PNG/PDF; GPU и плагины — позже |
| Потеря PNG при передаче DWG | Комплект с относительными путями, проверка наличия, инструкция |

## 13. Прототип (что уже доказано)

Каталог `prototype/` — исходное доказательство концепции на Python (numpy, OpenCV, ezdxf):

- `make_dwg.py` — синтетический исходник сада: слои, блоки растений с атрибутами `ВИД`/`D`, лист A3 с видовым экраном 1:100.
- `read_dwg.py` — чтение листа и видового экрана, правила «слой/блок → элемент», сборка сцены, рендер.
- `engine.py`, `objects.py`, `garden.py` — стили, бумага, тени, кроны из листовых кластеров, изгородь, миксбордеры, водоём, настил, плиты.
- Проверено: правки в CAD (перемещение, смена `ВИД`/`D`, новые блоки, смена слоя цветника) корректно отражаются при пересборке; A3 ≈ 8–10 с на CPU.

Код прототипа не является архитектурой продукта и будет перенесён в модули `src/` по разделу 4.

## 14. Исследование, на которое опирается ТЗ

- **Методики кафедр.** UC Davis, Landscape Architecture — «Digital Rendering: A Timesaving Guide» (Riha, 2009): гибридный рендер из ручных образцов, масштаб штриха соразмерен чертежу. University of Florida, LAA 2376c — гибридная подача как стандарт курса. ОНУ им. Мечникова, «Ландшафтна графіка та моделювання» (2026): порядок «контур → светлый тон → собственная тень → падающая тень», ≥ 3 оттенка на цвет, размеры крон в 1:200.
- **NPR.** Yessios (SIGGRAPH 1979) — компьютерная отрисовка камня, дерева, растений; Schumann et al. (CHI 1996) — эскизный рендер в CAD; Deussen & Strothotte (SIGGRAPH 2000) — перо для деревьев; Curtis et al. (SIGGRAPH 1997) — акварель, Kubelka–Munk; Bousseau et al. (NPAR 2006) — акварель на изображении.
- **ИИ в ландшафте.** Ye et al. (Environment and Planning B, 2025) — SD + ControlNet + LoRA для концептов; перерисовка целиком теряет точность чертежа и не связана с DWG — ниша подтверждается.
